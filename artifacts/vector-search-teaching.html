ทำไม "ค้นด้วยความหมาย" ถึงต่างจาก Ctrl+F

คอมพิวเตอร์เปลี่ยน "ข้อความ" เป็น ชุดตัวเลข (vector) — เหมือนให้พิกัดกับความหมาย ประโยคที่ความหมายใกล้กัน จะมีพิกัดอยู่ใกล้กัน แม้ ไม่มีคำร่วมกันสักคำ

→ ค้น "เบาหวาน" แล้วเจอเอกสารเรื่อง "public health" ได้ เพราะมันอยู่ในย่านความหมายเดียวกัน — นี่คือสิ่งที่ keyword search (FTS) ทำไม่ได้

embedding มาจากไหน

ข้อความ → โมเดล → ตัวเลข

"งานวิจัยเบาหวาน" → embedder (bge-m3) → [0.02, 0.91, -0.13, … อีก 1021 ตัว]

โมเดลถูกฝึกจากข้อความมหาศาลจนเรียนรู้ว่าคำ/ประโยคไหน "ความหมายใกล้กัน" → แปลงเป็นพิกัด 1024 มิติที่สะท้อนความหมาย · ไม่ใช่เวทมนตร์ — คือ pattern ที่เรียนจากข้อมูล

โค้ดจริง

vector search = cosine similarity (แค่นี้เอง)

หัวใจของ vector search คือสูตรเดียว — วัด "มุม" ระหว่าง 2 vector · มุมแคบ (cosine เข้าใกล้ 1) = ความหมายใกล้กัน · เดโมด้านบนคำนวณสูตรนี้สดในเบราว์เซอร์
// ความหมายใกล้กันแค่ไหน — คืนค่า 0..1
function cosine(a, b) {
  let dot=0, na=0, nb=0;
  for (let i=0; i<a.length; i++) {
    dot += a[i]*b[i];      // จุดตรงกันแค่ไหน
    na  += a[i]*a[i];
    nb  += b[i]*b[i];
  }
  return dot / (Math.sqrt(na)*Math.sqrt(nb));
}
// ค้น = เรียง doc ตาม cosine(queryVec, docVec) มาก→น้อย

สำหรับผู้สอน

gotchas — จุดที่คนมักงงตอนสอน vector

  • อย่าลงคณิตลึก — non-tech ไม่ต้องรู้ dot product/norm · พอแค่ "พิกัดของความหมาย + หาจุดใกล้กัน"
  • ย้ำว่า embedding ไม่ใช่เวทมนตร์ — โมเดลถูก "ฝึก" จากข้อความมหาศาลจนรู้ว่าคำไหนความหมายใกล้กัน
  • vector ≠ แม่นเสมอ — บางทีจับความหมายผิด (เช่น คำกำกวม) → ทำไม hybrid (FTS+vector) ถึงดีกว่าตัวเดียว
  • เดโมวันจริง: ใช้เดโมนี้ + FTS จริง — vector layer เต็มยังปิด (Ollama retired) อย่าเปิด Playground ที่ vector column ว่างบนเวที
  • ข้ามภาษาคือจุดขาย — ค้นไทย เจอ doc อังกฤษ (bge-m3 multilingual) → researcher ไทยที่อ่าน paper อังกฤษจะอิน
