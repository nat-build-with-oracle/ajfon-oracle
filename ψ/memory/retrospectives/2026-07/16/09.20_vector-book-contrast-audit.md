## Honest Feedback

1. **Two-pass fix instead of one, on the same root cause.** The dark-mode contrast bug got "fixed" at the CSS-class level first (iter 109-112), was called done, and then needed a full token-level rewrite (`apply_theme.py`) once Playwright's numeric audit exposed 1056 remaining failures. ## Lessons Learned

- When a rendering/theming bug traces back to a CSS-custom-property (design-token) system, fix it at the token level first — per-class overrides on top of a token cascade will look fixed for the cases you checked and silently fail for the ones you didn't. Verify with an automated, exhaustive measurement (e.g. compute contrast on every rendered text node), not a visual skim.
- Prove pipeline claims by executing them, not by writing them: a notebook with an `assert` self-check cell that runs headless (`nbconvert --execute`) is categorically more trustworthy than a notebook that "looks correct" — this session's Thai-embedder gap, the ANN scale-dependent benchmark, and the Chroma distance-metric trap were all real bugs the code caught, not things the author already knew to warn about.
- Before adopting any default library configuration (embedder, distance metric, index) for a teaching or production claim, measure it against at least one adversarial or non-English/non-default case — defaults are frequently tuned for English/majority-case data and silently fail on the exact input your teaching demo will use.
- On a machine with a system Python marked externally-managed, expect the first venv/kernel setup to be a blocking detour when a task suddenly requires real code execution (not just editing) — budget for it rather than treating it as an aside.
